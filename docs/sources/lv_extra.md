# LV extras (lv_monitored, lv_smart, lv_headroom_forecast)

Sources registered in `src/gridmap/sources.d/lv.yaml` (plus ENW/SPEN/UKPN LV sources already in sources.yaml).

- **lv_monitored**: ENW DFES monitored list (PreSense), SPEN lv_monitor, NPG lv-monitor-deployment-strategy (installed + shortlist), NGED lv-load-monitor-data (CKAN resource names = monitored secondary numbers, joined to norm/NGED/lv_site coords). UKPN and SSEN publish no list. No operator publishes the monitor vendor except ENW (PreSense).
- **lv_smart**: peak kW per smart meter per secondary substation, latest month. NGED (all), SPEN Wirral/Ayrshire (feeders summed; streamed and reduced into agg.parquet by the `smart_agg` fetcher, scheduled like any source (NGED: ~520 MB gz per month downloaded and discarded)), UKPN 21-substation sample (30k-row export cap), SSEN (below). NPG and ENW (installation counts) are not consumption feeds and are skipped.
  - **SSEN** (`ssen_sm_gql`, `os_codepoint`): the SSEN portal links a GraphQL API (POST https://gql.internal.datopian.com/v1/graphql, Hasura over BigQuery, CC BY 4.0). The `ssen_smart_meter_prod_*` tables return BigQuery 403 (broken permissions, checked 2026-11-12), so only the `ssen_smart_meter_dev_*` tables work: data ends 2024-09-05, so the layer carries one full day (2024-09-04, a Wednesday in summer: not a winter peak), property `as_of`. The `ssen_gql` fetcher (fetch/ssen_gql.py, POST, scheduled every 30d) saves raw gzip'd GraphQL pages: the feeder x postcode lookup (420,392 rows) and half-hourly usage per feeder (about 87k feeders x 45 slots, 3.9M rows, ~40 MB, ~500 requests at <=2/s, per-slot paging). Feeders are summed per secondary substation (first 10 digits of the 12-digit `dataset_id` = primary 4 + HV feeder 3 + secondary 3; the 3-digit `secondary_substation_id` alone is not unique), then peak kW = max half-hour Wh x 2 / 1000, same as other operators. No coordinates are published and SSEN lv_site ids (7-digit) do not match, so position = MPAN-weighted centroid of the substation's postcodes (OS Code-Point Open, OGL v3, `os_codepoint`, 90-day cadence, zip kept as `file`), snapped to the nearest SSEN `lv_site` within 250 m when one exists (property `loc` says which). Transformer rating is not joined for SSEN (a snap is not a verified match). Result (2026-11-12 fetch): 34,748 substations of 35,092; 33,006 snapped (95%), 1,742 centroid-only.
- **lv_headroom_forecast**: ENW dfes-lv-headroom monitored + unmonitored, single year/scenario (see layer description).

Layers are pmtiles points, minzoom 9. Tests: tests/test_extra_lv.py (fixtures in tests/fixtures/extra/lv/).
